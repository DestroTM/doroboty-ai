# PostHog browser analytics (Q4.3 Event Scout)

Slug: `posthog-analytics`
Created: 2026-11-18
Branch: `posthog/wizard-01a1ee4b2200` (PR #4, generated by the PostHog wizard, then reviewed and corrected)

## Goal

See a production pageview and a click (Autocapture) from the published Netlify site in PostHog **Activity → Live**, without sending persona data from places where people type or read it.

## Acceptance criteria

- Production builds initialise PostHog (EU project) with Autocapture on; `npm run dev` stays analytics-free unless `.env.local` opts in, and never crashes when the variables are missing.
- Netlify and the GitHub production check build identical assets, so the public project values live in the committed `.env.production` (the project token is public by design; no secrets).
- Element events (`$autocapture`, `$rageclick`, `$dead_click`, `$copy_autocapture`) are dropped on `#/app`, `#/aplikuj` and `#/auth`. The free-text `query` search parameter is redacted from every URL property. Identity carries persona ID and role, no name. Session recording is off.
- Hash routes stay visible: URLs keep the hash and every hash route change records a `$pageview`.
- `./scripts/verify` passes with PostHog configured; browser journeys never send traffic to the real project.
- FEATURES.md and the privacy page describe the actual behaviour.

## Review of the wizard PR and decisions

- The wizard threw an error at module load in development when variables were missing (blank page for `npm run dev` without `.env`). Replaced with a `console.info` and no initialisation.
- `.env.example` was ignored by `.env*` and never committed. `.gitignore` now allows `.env.example` and `.env.production`.
- With `defaults: "2026-08-30"` PostHog strips URL hashes (`disable_capture_url_hashes`). In this hash-routed SPA every event reported `/`, one pageview per load and the private-route filter could not match. Set `disable_capture_url_hashes: false` and `capture_pageview: { path, search, hash }`.
- The "no external requests" browser journeys failed (6/40) once the build had PostHog configured. Journeys now abort `*.posthog.com` and exclude it from those assertions; `tests/e2e/analytics.spec.ts` decodes stubbed batches instead.
- Duplicated `posthogConfigured` checks in eight files and `src/lib/posthog-logger.ts` were consolidated into `src/lib/posthog.ts` (guarded `capture`, `captureException`, `identifyPerson`, `resetIdentity`, `posthogLogger`, `sanitizeEvent`).
- Kept the wizard's product events, Error Tracking, Logs and starter dashboard (EU project 356236). Dropped the person name from `identify` and disabled dead clicks.
- PostHog filters headless browsers as bots; the analytics journey presents a desktop user agent only inside the test.
